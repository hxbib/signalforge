# Build the vertical slice

## One deployment

Python 3.11+, FastAPI + Uvicorn, same-origin HTML/CSS/ES modules, one SQLite file on persistent disk. One API process is enough for the demo. Add a single worker only for an explicitly authorized watch feed. Keep provider keys server-side. Serve the upload form at /. Store only a random opaque HttpOnly, SameSite session cookie. State-changing routes check same origin, session ownership and revision. Any route accepting an uploaded image limits encoded bytes to 5 MB, actual pixels to 16 MP, single-frame JPEG/PNG/WebP. Reuse live_smoke.clean_image to orient, reencode, strip metadata and bound the outgoing image. Keep user media transient; retain separately only if rights and consent permit an evaluation capture. Escape merchant strings as text, preserve safe merchant links, and avoid fetching submitted URLs on the server. A source adapter uses a known permitted origin and fixed paths, bounded responses, timeouts and backoff.

## Endpoint contract

| Method and path | Request | Response / behavior |
|---|---|---|
| POST /api/search | Multipart image, optional note, optional normalized crop, optional previously supplied ZIP. | 202 with run_id, revision and status. Enqueue one job per idempotency key. Empty note is valid. |
| GET /api/search/{id} | Session-owned run. Browser polls every second while pending; stop on terminal status or navigation. | state, goal, target, offers, coverage, progress and optional question. Use actual completed events only. |
| POST /api/search/{id}/answer | revision, opaque question_id, one allowed choice/ZIP/crop. | Validate against stored options, increment revision, rerun affected steps. Old answers return 409. |
| POST /api/search/{id}/watch | explicit watch command or click, optional cap. The server owns seller, rule and source. | active with scope + pause_url, needs_detail, or preview_only. Existing explicit authorization in the search note can invoke this internally after verification. |
| POST /api/watch/{id}/pause | Current session and revision. | Idempotent pause. UI can always undo a newly armed watch. |
| GET /api/search/{id}/proof | Session-owned run ID. | Real model job receipts, merchant rejection reasons and hypothetical effects, each labeled by origin. |

Choose run states `reading → searching → verifying → complete | partial | needs_detail | unavailable`. Partial is useful and may carry a compliant winner limited to the verified subset. Real sources may finish in a different order. A changed input gets a new revision; no late worker may overwrite it. Return 400 unsupported input, 413 upload too large, 404 unknown or foreign ID, 409 stale interaction, 429 on budget exhaustion. Do not expose API keys, raw URLs containing provider keys or untrusted error strings.

## Shared types and evidence

- **Goal**: operation, market US, currency USD, new condition, price basis item/delivered, fulfillment online_us / ship:<five-digit ZIP> / pickup:<verified location>, optional one-unit cap and comparator, explicit extra constraints. A user can ask for a product without naming a price. Unrepresentable hard constraints produce a scoped partial result.
- **Target anchor**: validated normalized trade identifier, canonical brand, MPN, variant values, required discriminating options, identity source and supporting evidence. `exact_variant_by_mpn` must be set by the trusted resolver only when that brand/MPN identifies this variant/pack. Never set it from the model's confidence. Without a unique mapping, keep candidates and abstain or ask.
- **Quote**: normalized offer dictionary for `buyer.evaluate` with seller, listing (variant-specific), gtin, source, url, read_at (UTC integer), currency, item_cents, new condition, stock, unconditional boolean and fulfillment. Delivered additionally requires shipping_cents, tax_cents, fees_cents. Zero is meaningful and requires support; missing is unknown. Normalize equivalent GTIN spellings before merging duplicate listings. Normalize canonical seller IDs using a reviewed alias table; marketplace merchants remain distinct from the marketplace operator.
- **Receipt**: source name, source type, read time, effective timestamp/cache age, item/variant ID, price basis, freshness and failure status. Raw content, if allowed at all, is transient. Log permitted metadata separately. Re-read stale facts and reject source timestamps in the future. Limit each comparison to a 120-second observation window; do not turn a cached response into a fresh receipt by calling the same function again.
- **Coverage**: count unique retailers attempted, responding, eligible, missing or blocked. Deduplicate seller aliases. A shopping-index discovery page is one provider and can contain many unverified seller leads. Keep them out of eligible coverage. Explicitly mark when a scope was not attempted or a source returned limited search results.
- **Watch**: session-owned target, feed_id, seller, variant, exact rule, source permissions, authorization origin, proof hash and revision. Use a transaction to store approval and activate only after confirming current inputs and source binding. The caller must enforce source permission and authorization before calling the lower-level Ledger. Feed input and active watch must name the same SKU and permissioned feed scope.

## Implement against these callables

1. `reference/find.py::parse_goal` yields a typed intent. `reference/deal_models.py::inspect_image` runs Neon + Decision 1 concurrently. Start both. Use the server's already-chosen image and crop for every arm. For a local barcode decoder, pass verified_scan to bind_target only when it independently decoded exactly one code in the identified target region. Clear disagreement with a genuinely new source or crop.
2. Run `shop.search` by text/image and `compare_offers.compare_now` by exact barcode, plus the non-Shop lanes in spec/RETAILERS.md. Build a real manufacturer crosswalk for no-barcode items. Use `deal_models.pair_verdict(..., True)` to screen competing text listings on this path. A model “match” is supporting evidence; ranking still requires verified identity and merchant facts. `deal_models.bind_target` makes the final source-bound Carbon selection. Never put store-specific SKU alone into a cross-merchant key.
3. Each adapter supplies normalized quote rows and a coverage outcome, including eligible, rejected, unknown and failed. `reference/buyer.py::evaluate(target, goal, offers, as_of)` is the single production ranking entry. Map display strings in the UI, no second price sort. `rank_verified.py` is the earlier item-only reference retained for regression compatibility; production uses buyer.evaluate. The Shop-only CLI is an integration probe.
4. Use returned eligible rows to render all tied sellers with their original URLs and times. Choose the cheapest genuinely observed near miss and its specific reason; avoid undated scraped claims. Only show “$X cheaper” if the two amounts have the same basis, currency and unit. Use a plain sentence for each near miss, preferably “$4 less, pickup only in…” or “Different set number.” Additional evidence belongs in an expandable drawer.
5. For a watch, reuse gemini_io.Proposal/bound_rule plus proof.py, autowatch.advance and ledger.py. Run the natural-language hard-constraint and source/permission checks first. Only build questions about distinctions that remain. Verify all invariants, match the subscriber's scope and store proof/permission revisions with one atomic activation; preserve explanation and pause. The worker reads only a permitted merchant export bound server-side. Persist source observations only as allowed.

**Authorized feed format.** The supplier atomically replaces a locally mounted JSON document with feed_id and observations. Each observation follows core.Seen: seller, variant, available (true/false/null), cents (integer/null), currency, t (merchant-observed UTC seconds), status. The operator verifies that the producer is authorized and that repeated reads and retention are permitted. Fresh merchant reads belong in an adapter owned by the catalog team. With that producer and a genuine active watch, run `python reference/poll.py private/watches.sqlite --authorized-feed private/merchant-feed.json`. The supplied worker has no Shop network client. Team-owned development data may demonstrate transitions with a development label.

## UI to implement

Full-screen single search on desktop or phone, generous product crop, price and seller readable on a projector. Optional note below the capture affordance. Put “Best verified offer,” selected edition, amount/basis, stock/fulfillment, coverage, time and merchant CTA above the fold. Add “Why a cheaper listing lost” when supported by real evidence. Show source failure alongside coverage rather than a blocking red error. Provide an accessible editable text alternative to pointer crop. Live region announces result once. Keep evidence and editable watch examples behind disclosure. No graph wall, chat transcript or table of pretend integrations. Test fresh session, blank note, messy photo, no winner, two sellers tied, one failure and back/refresh. Unit tests alone cannot confirm the browser path.
